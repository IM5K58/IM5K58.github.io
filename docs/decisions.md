# 설계 기록

무엇을 **하지 않기로 했는지**와, 그 결정을 뒤집을 조건을 적어 둔다.
새 기술이 떠오를 때 여기부터 읽는다. 조건이 충족되지 않았으면 하지 않는다.

전체 판단 근거는 2026-08-24 아키텍처 검토에서 나왔다.
독립 진단 2건(코드 품질·운영 안정성)으로 약점 35건을 모으고, 네 갈래 설계안을
각각 회의론자가 반박 검증했다. **네 안 모두 기각**됐고, 남은 문제는 구조가 아니라
실제 버그 몇 개였다.

---

## 다시 잴 숫자

6개월마다 재고, 임계를 넘으면 해당 트리거 항목을 꺼낸다.

| 지표 | 재는 법 | 2026-08-24 | 임계 | 넘으면 |
| --- | --- | --- | --- | --- |
| 글 목록 크기 | `wc -c posts/index.json` | 2,426 B (4편) | 30 KB (~50편) | T2 페이지네이션 |
| 이미지 용량 | `du -sh assets/` | 11 MB | 30 MB | T8 이미지 외부화 |
| 노션 글 수 | index.json의 `source: notion` | 2편 | 10편 | T3 변환기 테스트 |

숫자로 안 재지는 트리거 하나였던 T1(**"링크 보냈는데 미리보기가 비어서 민망하다"**)은
2026-08-25에 해소했다 — 아래 "글마다 미리보기 껍데기" 항목 참고.

## 하지 않기로 한 것

### 2026-08-25 · 태그 페이지 — ESM 트리거가 왔는데 모듈은 안 썼다
`tags.html` 이 세 번째 목록 페이지다. 아래 "ESM 전면 전환" 항목에 적어 둔
뒤집을 조건이 정확히 왔다. 그런데 열어 보니 **전제가 틀렸다** —
"공통화하려면 모듈이 필요하다"고 썼지만, 기존 전역 객체 방식(Posts/Render/Theme)에
`js/ui.js` 를 하나 더 얹는 것으로 끝났다. **ESM 기각 유지.**

효과: 아카이브 페이지가 121줄 → 43줄. esc 구현 4벌 → 2벌(ui.js, admin.js).
필터 칩·연도 묶기·글 표 마크업은 각각 1벌만 남았다. 세 페이지를 더 만들어도
새 중복이 생기지 않는다.

**대신 새 실패 모드가 하나 생겼다**: 페이지가 의존하는 스크립트 파일이 늘었다.
캐시된 예전 HTML(ui.js `<script>` 없음)에 새 page-*.js 가 얹히면 `UI is not defined`
로 죽고 화면이 통째로 빈다. 실제로 개발 중에 밟았다. 각 페이지 스크립트 맨 앞에
`typeof UI === "undefined"` 가드를 두어 "새로고침해 주세요"라도 뜨게 했고,
글 상세는 본문이 핵심이라 UI 없이도 렌더되게 esc 대체 구현을 뒀다.

**admin.js 의 esc 는 합치지 않았다.** 관리 화면은 런타임 오류가 곧 원고 손실이라
전역 하나를 더 의존하게 만들 이유가 없다. 2벌은 남겨 둔 값이다.

### 2026-08-25 · 글마다 미리보기 껍데기를 생성한다 (T1 해소)
`post.html` 한 장으로는 링크 미리보기가 전부 "Kyumswriting"으로 보였다.
크롤러가 JS를 안 돌리기 때문이고, 정적 호스팅에서 주소 하나로 글마다 다른
`<head>`를 내주는 방법은 없다. **채택** — `posts/index.json`이 바뀌면 액션이
`p/<slug>.html` 과 `sitemap.xml` 을 다시 만든다 (`tools/build-meta/generate.mjs`).

이건 앞서 기각한 "빌드 파이프라인"과 다르다. 껍데기는 `<head>`만 채운 `post.html`
복사본이고 본문은 여전히 브라우저가 그린다. 렌더러를 Node로 옮기지 않았으므로
생성이 실패해도 사이트는 멀쩡하고 미리보기만 빠진다 — **연성 실패**다.
빌드 파이프라인을 기각한 이유(실패하면 사이트가 안 뜬다)가 여기엔 없다.

**새로 생긴 비용 셋**, 지켜볼 것:
- 생성물이 저장소에 커밋된다. 글 하나 올리면 커밋이 둘(글, 껍데기)이 된다.
- 글을 올리고 껍데기가 배포되기까지 1~2분 창이 있다. 그 사이 링크는 404가 되고,
  `404.html`이 `post.html?slug=` 로 되돌려 보낸다. 안전망이 없으면 막다른 길이다.
- `post.html` 구조가 바뀌면 생성기가 죽는다. 일부러 그렇게 했다 —
  조용히 빈 메타를 뿜는 것보다 액션이 빨갛게 뜨는 편이 낫다.

**뒤집을 조건**: 글이 200편을 넘어 `p/` 의 파일 수가 저장소를 훑기 불편해질 때.
그때는 껍데기를 지우고 Cloudflare Workers 같은 앞단에서 메타만 갈아끼운다.

### 2026-08-24 · 콜아웃 종류 라벨 (NOTE / TIP …)
기술 색인 방향 시안의 콜아웃에는 왼쪽 색 블록 위에 등폭 대문자 라벨이 있다.
**넣지 않음** — 예전에 렌더 단계에서 "팁" 같은 라벨을 자동으로 붙였다가 사용자가
직접 걷어내라고 했던 장치다. 노션 원문에 없는 글자가 화면에 생기는 게 문제였고,
그 이유는 CSS `::before`로 넣어도 그대로다. 종류는 왼쪽 8px 색 블록만으로 구분한다.
**되살리는 법**: `css/post.css`의 `.prose .callout::before` 주석을 풀면 된다.
색깔별 `--co-label` 값은 이미 다 정의돼 있다.

### 2026-08-24 · 홈 카드 "NO FIG" 칸
썸네일 없는 글의 오른쪽 150px 칸을 `NO FIG`로 채우는 안(시안에 있던 그대로).
**기각** — 올린 당일에 뺐다. 목록의 칼럼 리듬을 지키려던 건데, 대가가
"없다"는 말을 글마다 반복해서 읽히는 것이었다. 없는 걸 굳이 알릴 이유가 없다.
지금은 썸네일이 있는 카드에만 칸이 붙고, 없으면 본문이 카드 폭을 다 쓴다.
**뒤집을 조건**: 없음. 칸을 다시 채우고 싶어지면 그건 빈 칸 문제가 아니라
카드에 넣을 다른 정보(글자 수, 읽는 시간 등)가 생겼다는 뜻이다.

### 2026-08-24 · ESM 전면 전환
`<script>` 순서가 코드에 선언되지 않는 게 싫어서 js 9개를 모듈로 쪼개는 안.
**기각** — 그 문제로 깨진 커밋이 68커밋 중 0건이었다. 대가는 테스트 0개 상태에서
동작 중인 1,469줄을 손으로 재작성하는 것이다.
**뒤집을 조건**: 세 번째 목록 페이지(태그 페이지 등)가 필요해질 때.
그때는 `tab()` 중복이 3벌이 되고, 공통화하려면 모듈이 필요하다.
→ 2026-08-25에 왔다. 모듈은 필요 없었고 `js/ui.js` 하나로 끝났다. **기각 유지.**

### 2026-08-24 · tsconfig + strict 타입 시스템
**기각** — strict를 전부 끄면 에러 48개, `strictNullChecks`만 170개, full strict 365개.
그런데 발견 가치는 48개 안에서 포화한다. 대신 `// @ts-check` 주석을 쓴다.
**뒤집을 조건**: 없음. 필요해지면 그때 tsconfig를 얹으면 되고, 오늘 붙인 주석이 그대로 입력이 된다.

### 2026-08-24 · CDN 라이브러리 벤더링
marked·DOMPurify·KaTeX를 `assets/vendor`로 내리는 안(약 1.15 MB).
**기각** — 현재 URL이 전부 버전 고정이라 CDN은 지금도 아무것도 패치해주지 않는다.
공급망 노출은 SRI로 훨씬 싸게 닫힌다. 결정적으로, 벤더링하면 DOMPurify 업그레이드가
"URL 숫자 하나"에서 "설치+빌드+커밋"이 된다 — **XSS 방어선을 가장 갱신하기 어려운
형태로 바꾸는 것**이라 막으려던 위협과 반대 방향이다.
**뒤집을 조건**: jsDelivr가 실제로 장애를 내거나 차단돼 사이트가 안 뜰 때.

### 2026-08-24 · 빌드 파이프라인 + 산출물 커밋 + CI 게이트
**기각** — 정당화 근거로 제시된 코드 중복이 실제로는 8줄이었다. 반대로 산출물 커밋은
"소스 ≠ 서빙 파일"이라는 오늘 없는 실패 모드를 만든다. 실제로 자주 하는 일이
"CSS 한 줄 고치기"인데 그게 Node 필요 작업이 된다. **1인 저장소에서 상시 빨간 CI는
중복보다 나쁘다.**
**뒤집을 조건**: 소스 파일이 20개를 넘고 손으로 맞추는 중복이 3벌 이상 생길 때.
→ 2026-08-25 기준 파일은 23개로 넘었지만 중복은 오히려 줄었다(최대 2벌).
두 조건이 함께여야 하므로 **트리거 안 걸림.** 파일 수만으로는 꺼내지 않는다.

### 2026-08-24 · Astro / SSG 전면 전환
**기각** — 최대 이득이라던 "index.json 공유 쓰기 제거"가 프레임워크를 필요로 하지 않는다
(워크플로 스텝 60줄이면 된다). "빌드를 흡수한다"도 사실이 아니었다 — 에디터 번들은
68커밋 동안 한 번도 재빌드되지 않았다. 빌드 1회를 수백 회로 바꾸는 건 흡수가 아니라 추가다.
실패 모드도 "글 하나 깨짐"에서 **"알림 없는 사이트 전체 정지"**로 나빠진다.
**뒤집을 조건**: T1(공유 카드)이 왔는데 프리렌더 60줄로 감당이 안 될 때.
그때도 먼저 60줄을 시도한다.
→ 2026-08-25에 T1이 실제로 왔고, 생성기 180줄로 끝났다. **기각 유지.**

### 2026-08-24 · 테스트 하네스 + CI 게이트
**기각** — 1순위로 지목된 인덱스 검사기가 **실제로 일어난 손상 2건 모두에 초록불**이었다.
불변식이 "매니페스트 내부 정합성"만 보는데 실제 실패 모드는 "같은 글이 다른 slug로 둘"이라
검출기가 눈앞의 손상을 정상이라고 부른다.
**뒤집을 조건**: T3(노션 글 10편) 또는 T7(레이아웃 버그 3회 재발).
그때는 겨냥할 불변식이 명확해진 뒤다.

### 2026-08-24 · 캐시버스터(`?v=`) 제거
**유지하기로 함** — Pages 캐시가 10분이라 없으면 새 글이 그동안 안 보인다.
배포 폴링도 즉시 반영에 의존한다. 제대로 고치려면 빌드 시점 해시가 필요하고, 그건 빌드다.
**뒤집을 조건**: 빌드를 도입하는 날.

### 2026-08-24 · 검색 본문 인덱싱 / 임베딩 검색
본문까지 검색하려면 md 전량 fetch 또는 검색 인덱스 생성(=빌드)이 필요하다.
임베딩은 한국어라 다국어 모델이 필요한데 양자화해도 약 120 MB — 본문 전체가 50 KB인데
모델이 2,400배다.
**뒤집을 조건**: 글이 30편을 넘고 "분명 썼는데 안 나온다"를 실제로 겪을 때.
그때도 **본문 전문검색(md lazy fetch + 가중치 + 스니펫)이 먼저**고, 임베딩은 그 다음이다.

## 지키기로 한 것

- **루트에 `package.json`·`tsconfig.json`·`node_modules`가 없다.** `python -m http.server`
  한 줄로 개발한다. Node는 `tools/` 아래 두 도구만 쓴다.
- **글 커밋 후 1분 내 반영.** 빌드 단계를 끼워 이 특성을 잃지 않는다.
- **admin은 md와 index.json만 쓴다.** 파생물을 늘리지 않는다.
  미리보기 껍데기를 액션에 맡긴 것도 이 불변식을 지키려는 선택이다 —
  글 쓰는 경로(관리 화면·노션) 둘 다에 생성 코드를 넣지 않았다.
- 이 저장소의 최대 자산은 코드 품질이 아니라 **움직이는 부품이 적다**는 것이다.
